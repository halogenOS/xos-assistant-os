2026-09-02 17:53  The prompt is the head of every successor, and a refusal ends the process

The startup walk used to fork a channel's whole ledger and append the current
system prompt behind it, so every conversation it touched carried its prompt
as its newest block. A statement the database refused counted as a passing
failure, so the unattended compaction of such a conversation forked a
temporary conversation, paid for a summary turn over half the history, failed
at the thread's own prompt, and started over on the next wake.

The walk now composes the successor the other way: an empty fork, the current
prompt as its first block, then the source's join rows in the range the walk
chooses. A conversation whose prompt is not its first row is re-forked for
that reason alone, taking the rows written ahead of the misplaced one as its
history, so a database already in the old shape is repaired once, before
anything is served. A statement the database refuses by a rule is fatal now:
the compaction driver raises the process's exit and stops watching instead of
trying again, and the binary ends the run for the supervisor to replace.

The composition replaces the fork-detach-append door in the session module and
takes its range as an argument, because only the walk knows where the old
prompt sits. The classification moves the refused class in beside the two
classes that already ended the process, and the assembly gains one signal for
a failure with no caller to fail, which the binary waits on beside the
termination signal. The tests cover the composition, the repair walk over a
shape built in SQL, the classification, a refused compaction paying for one
turn and never a second, and a re-forked channel compacting end to end; the
suite's injected append fault moves to an arithmetic overflow, so the proofs
about a redelivered failure keep the class they are about.

Observed in the deployed bot: every live group's compaction failed on the
prompt rule and was retried on every wake, each retry paying for a summary of
the first half before reaching the same refusal.

Nothing is deleted to repair anything. The source keeps every block it had and
the successor shares them through the junction, so what changes is which rows
a conversation holds and in what order, never the record of what was said.
